# 场景Agent依赖通用能力，通用能力不依赖场景

2026-10-15，设计评审确认：Writing、Coding及未来的Personal Agent均属于场景层，核心Agent不以这些场景建立固定类型。场景拥有模板、工具组合、交互入口、验证与启用政策；通用资产、执行、Memory和context_builder不导入场景模块，也不根据场景名称分支。

后续Q13选择独立场景应用：本项目只提供通用服务和API/SDK，不装配Writing/Coding场景，也不依赖其客户端、审批表或产品配置。场景应用拥有自己的部署、业务状态与协议，通过通用API/SDK组合能力；已有场景具体由哪个仓库承接，在实施前落实，不在本轮文档审查中修改或发布其他仓库。

用户后续明确本项目只负责通用Agent框架；外部业务模块由各自任务设计，本轮不定义其组织、协议、存储、迁移或跨库事务。

新场景及独立模块通过通用能力完成授权的配置、执行、记忆和查询，不要求修改底层的产品分类。框架只保证自己的Run/Session/消息/事件及资产事务，不承诺外部业务状态与执行跨数据库原子；具体外部流程不在本设计中确定。
