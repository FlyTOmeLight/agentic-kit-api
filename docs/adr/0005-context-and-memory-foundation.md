# 首版上下文与Memory采用独立契约组合

2026-10-15，设计评审确认：本轮实现context_builder和Memory基础读写、版本、召回与冻结，后台提炼、自主学习和自动晋升后置。Memory管理可复用内容，builder负责模型输入选择与预算，执行存储负责事实及快照的一致提交；通过规范化数据契约和集中适配组合，便于以后单独设计或提取，不提前增加独立服务或插件框架。

同一Run在接受时固定记忆内容与版本，后续纠正影响新Run；模型调用、重试和接管沿用原快照。这样长任务不会因记忆更新改变恢复输入，运行中刷新留待后续独立设计。

Q15确认首版默认关闭Memory，普通聊天和内部应用只有本次请求显式开启才召回。关闭、开启但无匹配及读取失败分别处理；选择进入幂等意图，解析内容和政策随Run冻结。这让记忆使用成为明确的执行输入，人工维护记忆不会自动改变后续运行行为。

Q16确认首版不做摘要式上下文压缩：每轮模型请求前先裁低相关Memory和最旧完整历史，保留当前输入与完整工具链，仍超限则明确失败、不自动重试。完整事实与冻结材料继续保存；摘要压缩及其事实保留、冻结和恢复规则留待后续独立设计。

2026-10-16 补充：复用artifact-go内容版本的修订提案见 [ADR-0008](0008-memory-artifact-versions.md)。它调整内容存储与维护事务边界，保留本文的人工维护首版、默认Off、Run完整冻结及裁剪规则；接入前提与实施状态由[Memory设计](../memory-design.md)说明。

2026-11-09 补充：用户确认先实施模型预算与工具大输出保护，再实施历史两级折叠。新Run使用`context-v2`，允许工具结果首尾预览；历史先保留问答、折叠工具过程，仍超限才整轮淘汰。旧`context-v1`快照保留原策略。该变更扩展Q16的模型输入投影规则，原始步骤、消息和冻结材料仍完整保存，不引入LLM摘要。具体预算、折叠条件及状态见[框架设计§6.6](../refactoring-design.md#66-上下文管线与-memory-基础版)。
