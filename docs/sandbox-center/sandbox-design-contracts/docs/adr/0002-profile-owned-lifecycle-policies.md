# 平台按场景发布生命周期策略

平台通过固定版本的 Profile 发布经过验证的环境复用、文件保存和进程保留组合。调用方选择 Profile，并在其公布的范围内调整超时；自动 Coding 任务默认按任务复用、完成后保存必要数据并销毁环境，持续开发和会话任务使用各自的 Profile。

这个边界避免调用方自由组合出无法兑现的保存与恢复承诺，代价是新组合需要平台验证后发布。环境、文件和进程的寿命分别定义：保留环境不意味着保留进程，保存文件不意味着恢复进程；断线也不等于释放租约。必要保存失败按[保存保护决策](0004-block-deletion-on-required-save-failure.md)保留文件并阻止正常销毁，具体场景参数由发布配置确定。

隔离等级也由 Profile 固定，默认使用 Hardened；仅对经过平台验证的受控任务开放 Standard Profile。这个选择保留受控工具的兼容性与成本空间，同时避免 Agent 生成或外部代码默认进入普通容器。调用方最低隔离要求只增加筛选约束，容量不足或不兼容不能触发自动降级。
