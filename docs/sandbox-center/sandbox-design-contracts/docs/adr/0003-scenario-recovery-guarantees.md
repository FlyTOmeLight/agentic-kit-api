# 按场景确定文件恢复承诺

自动 Coding 默认使用 EphemeralCopy 工作区和 Checkpointed 恢复等级，节点故障后恢复到最近成功发布的有效检查点，检查点之后的修改可能丢失。持续开发使用 PersistentVolume 和 Persistent 恢复等级，恢复范围以底层存储保证为准，并在重新挂载前隔离旧写者。

这一划分让自动任务可使用干净预热池，同时为持续开发保留持久工作区；代价分别是检查点之间可能丢失修改，以及持久卷挂载和故障隔离成本。两者都不恢复原进程或内存，由 Agent 平台核验会话与外部结果后决定如何继续；没有成功检查点时不宣称已恢复任务修改。

检查点时机由 agentic-kit 在业务阶段显式决定，沙箱中心负责写入静止验证、保存和发布确认，不设置自主周期保存任务。这样阶段选择归 Agent 平台，文件一致性归沙箱；代价是恢复点的新旧取决于调用方实际完成的保存，没有固定周期的数据丢失上限。沙箱控制循环仍负责完成已受理请求及结果对账。
