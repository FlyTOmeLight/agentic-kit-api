最关键的故障链

01 · 创建

60 秒环境期限

启动脱离进程组的 writer，持续写独立卷。

02 · 注入故障

杀死管理服务

确认管理容器退出码 137，执行容器继续存活。

03 · 超过期限

继续写、继续执行

文件仍增长，直连 execd 也能提交新命令。

04 · 恢复

管理服务补回收

环境最终删除、文件保留；过期执行窗口已经发生。

建议：继续复用后端，把接管边界补完整

本轮不足以支持全面替换 AIO。execd 仍适合作为命令与文件场景的候选；需要浏览器和组合工具时，AIO 仍有价值。二者都不能仅凭现有接口直接声明满足本项目的接管协议。

  1. 本地执行保护：控制面失联后，受保护组件仍按期限停止用户进程和写入入口，并保留工作区。
  2. 持久执行回执：派发前确定稳定操作 ID，响应丢失先查询；不能确认是否执行时保留 Unknown，不自动重发。
  3. 下一步将已有 supervisor 原型与一个实际数据面组合，在目标 Kubernetes 环境验证命令、文件和所有写入入口。原型通过不等于正式接入完成。

本轮覆盖

真实 Docker backend + execd，固定发布镜像 digest，独立卷与本地回环端口。完整测试主体耗时 151.62 秒；失败断言原样保留，代表尚未满足项目要求。

镜像内部包版本显示 0.1.0.dev0，因此以发布清单及 digest 标识实验对象。流解析、TTL 下限和动态端口问题已从探针中修正。

没有验证的部分

OpenSandbox Kubernetes / FastSandbox、gVisor / Kata、续租和 epoch、文件 API / PTY / 浏览器入口、节点故障；也没有实测 E2B 或 Daytona。

本结果不代表所有 OpenSandbox 配置都同样失败。没有修改业务 API/worker，也没有部署或提交代码。
